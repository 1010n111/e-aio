## 1. 引言

### 1.1 编写目的

本文档定义「企业级一体化管理系统（e-aio）」的软件需求，作为概要设计、详细设计、开发、测试与验收的依据。读者为项目发起人、产品经理、架构师、开发人员、测试人员、早期采用企业与开源贡献者。

### 1.2 项目范围

本系统为**通用能力大一统 + 业务逻辑按企业定制**的企业级一体化管理系统，覆盖 OA、CRM、库存、财务、工作流、审计、权限、审批、AI 等通用能力，并提供主数据与配置化定制底座。

**约束（贯穿全文）**：

| 编号 | 约束 | 说明 |
|------|------|------|
| C-01 | 非 SaaS | 仅支持自托管部署（Self-hosted），不提供多租户云托管商业服务 |
| C-02 | 全开源 | 系统全部开源，接受他人 PR |
| C-03 | 单体架构 | 不采用微服务，采用 Spring Modulith 模块化单体 |
| C-04 | Vibe Coding | 采用 AI 辅助的 Vibe Coding 开发范式 |
| C-05 | 开源优先 | 技术选型能用开源的就用开源 |
| C-06 | 母子公司 | 权限体系支持母子公司（集团-子公司）多级组织架构 |
| C-07 | 双审计 | 审计包括系统操作审计与财务审计 |

### 1.3 产品概述

**产品定位**：通用能力平台 + 定制业务逻辑 + 全开源自托管。平台内置 OA、CRM、库存、财务、工作流、审计、权限、审批、AI 等通用能力作为"大一统底座"；企业个性化业务逻辑（行业业务实体、专属流程、定制表单报表）通过主数据与配置化能力按需搭建。

**部署模型**：自托管（Self-hosted），企业自行部署于自有服务器/私有云，数据完全自主可控。

### 1.4 术语表

| 术语 | 定义 |
|------|------|
| 模块化单体 | 单一部署单元内按业务域划分模块的架构风格（Spring Modulith） |
| 通用能力 | 平台统一提供的可复用功能（OA、CRM、权限、审计、审批、工作流等） |
| 业务模块 | 按企业/行业定制、承载具体业务逻辑、单向调用通用能力的模块 |
| 配置化定制 | 通过主数据、字典、表单/流程配置实现业务适配的能力 |
| Vibe Coding | AI 辅助编码，以自然语言驱动、人机协作迭代的开发范式 |
| 母子公司 | 集团总部（母公司）与下属公司（子公司）的多级组织架构 |
| RBAC | 基于角色的访问控制（Role-Based Access Control） |
| ABAC | 基于属性的访问控制（Attribute-Based Access Control） |
| SoD | 职责分离（Separation of Duties），不相容岗位互斥 |
| 数据权限 | 按组织/部门/责任人等维度对数据行的访问控制 |
| WORM | 一次写入多次读取（Write Once Read Many），审计防篡改 |
| 主数据 | 跨业务共享的基础数据（客户、供应商、物料、科目等） |
| 共享访问 | 单体架构下各模块通过公共 API 实时读取主数据，不分发复制 |
| RAG | 检索增强生成（Retrieval-Augmented Generation） |
| 自托管 | Self-hosted，用户自行部署与运维 |
| PR | Pull Request，代码合并请求 |
| OCR | 光学字符识别 |

### 2.2 用户角色

| 角色 | 说明 | 权限要点 |
|------|------|----------|
| 系统管理员 | 平台运维、模块启停、参数配置 | 全部管理权限 |
| 集团管理员 | 集团级配置、权限模板下发、跨公司审计 | 全集团数据权限 |
| 子公司管理员 | 子公司内部角色、流程、数据权限配置 | 本公司数据权限 |
| 业务用户 | 日常业务操作（单据、审批、报表） | 按角色 + 数据权限 |
| 审批人 | 审批待办处理（含跨公司审批） | 审批权限 + 数据权限 |
| 审计员 | 审计查询、报表导出、审计报告 | 审计权限（分级） |
| 财务人员 | 凭证、账务、报表、对账 | 财务权限 + 财务审计 |
| 外部开发 | 基于 OpenAPI/Webhook 集成开发 | 受限 API 权限 |
| 移动用户 | 移动端审批、业务处理 | 与 Web 权限一致 |

### 2.3 运行环境

| 项目 | 要求 |
|------|------|
| 服务端 | 自托管，Linux/Windows 服务器或容器化部署 |
| 数据库 | PostgreSQL（主库）、Redis（缓存/会话）、ClickHouse（数仓，可选） |
| 浏览器 | Chrome / Edge / Firefox 最新版本 |
| 移动端 | H5 / 小程序 |
| 信创 | 麒麟/统信 OS、国产 CPU、达梦/人大金仓数据库（适配规划） |

### 2.4 假设与依赖

- 企业具备自托管部署与运维能力（或借助社区运维支持）。
- 开源社区持续贡献（接受 PR，但主线由核心维护组保障）。
- 大模型服务由企业自选（企业自有或第三方，经 AI 网关适配）。

## 4. 非功能需求（NFR）

> 编号规则：NFR-{类别}-{序号}。

### 4.1 性能

| 编号 | 需求 | 指标 |
|------|------|------|
| NFR-PERF-01 | 并发能力 | 单实例支持 2,000 并发用户 |
| NFR-PERF-02 | 接口响应 | 常规接口 P95 < 500ms；审批流程节点响应 < 2s |
| NFR-PERF-03 | 列表查询 | 百万级数据分页查询 P95 < 1s |
| NFR-PERF-04 | Excel 导入导出 | 10 万+行流式处理，内存峰值可控 |
| NFR-PERF-05 | 报表查询 | 集团汇总报表 P95 < 5s（数仓支撑） |

### 4.2 可用性

| 编号 | 需求 | 指标 |
|------|------|------|
| NFR-AVAIL-01 | 可用率 | 单机 99.5%；集群 ≥ 99.9%（目标） |
| NFR-AVAIL-02 | 部署 | Docker Compose 一键部署；支持多实例横向扩展 |
| NFR-AVAIL-03 | 容灾 | 数据库主从、备份恢复演练（RPO ≤ 24h、RTO ≤ 4h 起步） |

### 4.3 安全

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-SEC-01 | 传输安全 | HTTPS/TLS 全链路加密 |
| NFR-SEC-02 | 存储安全 | 敏感字段加密存储（AES-GCM）、密钥管理 |
| NFR-SEC-03 | 脱敏 | 手机号/证件/账号展示脱敏 |
| NFR-SEC-04 | 数据分类分级 | 按 SRS 数据分类分级执行访问控制 |
| NFR-SEC-05 | 导出管控 | 敏感数据导出水印与审批 |
| NFR-SEC-06 | 等保 | 目标三级（身份鉴别、访问控制、安全审计等） |
| NFR-SEC-07 | OWASP | 防注入/XSS/CSRF/SSRF，依赖漏洞扫描 |
| NFR-SEC-08 | 审计安全 | 审计日志 WORM 防篡改、独立备份 |
